# Legacy Stage 4 v0.2 Specification — Hybrid Metric 3D Player Reconstruction

This document describes the retained ablation/regression path. It is not the v0.3 production contract.

## 1. Mission

For every Stage-3 candidate track and usable frame, reconstruct metric anatomical anchors

\[
J_{t,j}=(X,Y,Z)\ \mathrm{m}
\]

in the frozen Stage-1 pitch coordinate system:

- origin: pitch centre;
- X: goal-to-goal;
- Y: touchline-to-touchline;
- Z: upward;
- units: metres.

Stage 4 is neutral to attacking direction. It exports pitch X, not goalward `q=sX`.

## 2. Inputs

Required:

- `tracked_pose_2d_state.json` from Stage 3;
- Stage-1 `CameraState` JSON timeline.

Production hybrid path additionally uses:

- `rtmw3d_initializer_cache.jsonl` generated by the official RTMW3D worker.

Stage-3 coordinates must be `RAW_DISTORTED_PIXEL` and image dimensions must exactly match the corresponding Stage-1 CameraState. No implicit resize is allowed.

## 3. Canonical optimized skeleton

Stage 4 preserves the RTMW3D raw 133-point cache, but optimizes only `METRIC_POSE_23`:

\[
23=17\ \text{COCO body}+6\ \text{foot landmarks}.
\]

Fine face/hand points are not optimized because broadcast footage does not reliably support their metric depth.

The current project-scope candidate mask excludes elbow and wrist anchors from downstream legal-body geometry while retaining shoulders. Arm points may still contribute kinematic information.

## 4. Hard calibrated-camera ray parameterization

Each validated image point \(p_{t,j}=(u,v)\) defines a Stage-1 calibrated world ray

\[
J_{t,j}(\lambda)=C_t+\lambda_{t,j}d_{t,j},\qquad \lambda>0.
\]

The optimizer solves \(\lambda\), rather than unconstrained XYZ. This makes Stage-3 image coordinates a hard observation: the reconstructed point reprojects to the same calibrated image ray by construction.

The implementation delegates raw-pixel distortion handling to the Stage-1 camera model. Stage 4 never performs an extra independent undistortion step.

## 5. Hybrid objective

The engineering objective is

\[
E =
 w_bE_{bone}
 +w_dE_{depth\ prior}
 +w_gE_{ground}
 +w_nE_{nonpenetration}
 +w_tE_{temporal}
 +w_pE_{pitch}
 +E_{height}.
\]

### 5.1 Relative 3D prior

RTMW3D-L supplies a relative-depth pattern only. Let \(\tilde z_{t,j}\) be the raw third channel centred on the hip root and robustly normalized. Camera-space relative depth is constrained by

\[
D_t(J_{t,j})-D_t(J_{t,root})\approx \beta\tilde z_{t,j},
\]

with a track-level signed scale \(\beta\). RTMW3D x/y and global translation are not used as final world measurements.

### 5.2 Anthropometric prior

Broad bone-length ratios are applied relative to a latent track height \(H\). Height has a weak prior and broad bounds; the implementation does not assume all players are 1.80 m.

### 5.3 Ground/contact constraints

Approximate left/right foot proxies use ankle as the primary anchor and heel/toe points only as refinement evidence. A temporal heuristic gives contact likelihoods. For likely contacts, ankle and foot-surface Z receive soft ground constraints; no foot is unconditionally forced to `Z=0`.

### 5.4 Non-penetration

Joints below a small negative tolerance receive a hinge penalty. This is a physical sanity constraint, not a claim that every foot is grounded.

### 5.5 Temporal smoothness

For consecutive track frames, Stage 4 penalizes world-space second differences

\[
J_{t+1,j}-2J_{t,j}+J_{t-1,j},
\]

with looser tolerances for fast-moving limbs/feet than for torso/head.

## 6. 2D temporal fill

A missing Stage-3 point can be interpolated only when finite observations exist on both sides within a small configured gap. Such evidence is explicitly labelled `STAGE4_TEMPORAL_2D_INTERPOLATION`; raw Stage-3 points are never overwritten.

## 7. Output

`metric_pose_3d_state.json` contains:

- source Stage-1/Stage-3 provenance;
- world-frame definition;
- 23 world XYZ anchors per observation;
- original Stage-3 raw pixel coordinates;
- initializer-relative-depth provenance;
- foot-contact diagnostics;
- derived head/shoulder/pelvis/foot proxies;
- optimizer diagnostics;
- optional selected-frame XYZ sensitivity intervals;
- selected-frame quality and coverage.

`stage5_handoff.json` exposes only the stable downstream contract. Stage 5 constructs legal-body volumes/surfaces and goalward extents.

## 8. Quality semantics

- `VALID`: optimizer converged, initializer available, enough temporal frames, no major non-physical penetration.
- `DEGRADED`: usable metric estimate but missing initializer, short temporal context, or other quality limitation.
- `REJECTED`: optimizer failed/non-finite.
- `MISSING`: no usable selected-frame Stage3+Camera observation.

## 9. Explicit non-goals

Stage 4 does not:

- identify teams;
- decide which team attacks;
- identify the passer/toucher;
- create the final legal-body surface;
- project elevated body parts onto the pitch with a homography;
- trust monocular RTMW3D global placement;
- resolve true toe geometry beyond what broadcast evidence supports.
